# گزارش امنیت و وضعیت فعلی

تاریخ بررسی: 2026-11-18  
پروژه Supabase: `shop-attendance`  
شناسه پروژه: `lhzxaewsckpohykfnzpz`

> این سند گزارش بررسی اولیه است، نه گواهی امنیت یا تست نفوذ. هیچ تغییری در پایگاه داده در این بررسی اعمال نشده است.

## یافته‌های مثبت
- RLS روی جداول `admins`، `employees`، `attendance_records`، `audit_log` و `settings` فعال است.
- دسترسی مستقیم جدول‌ها برای نقش‌های عمومی `anon` مشاهده نشد؛ دسترسی خواندن مستقیم به برخی جداول برای `authenticated` با RLS محدود شده است.
- سیاست‌های خواندن جداول اصلی به `is_admin()` متکی‌اند و سیاست به‌روزرسانی تنظیمات نیز بررسی مدیر را دارد.
- توابع مدیریتی از `_require_admin()` استفاده می‌کنند؛ این تابع هویت ایمیل JWT را با جدول مدیران تطبیق می‌دهد.
- توکن QR یکتا است، PIN به شکل هش‌شده ذخیره می‌شود و تلاش‌های ناموفق باعث قفل موقت می‌شوند.
- شاخص یکتای جزئی `one_open_record_per_employee` از وجود بیش از یک رکورد باز عادی برای هر کارمند جلوگیری می‌کند.
- مجوز CREATE برای نقش‌های `anon` و `authenticated` در schemaهای `public` و `extensions` مشاهده نشد.

## موارد نیازمند اقدام
### ۱. توابع SECURITY DEFINER
مشاور امنیت Supabase سه تابع کیوسک را برای نقش `anon` و ۱۲ تابع را برای نقش `authenticated` قابل اجرا گزارش کرده است. دسترسی عمومی به `kiosk_scan` و `kiosk_my_records` ممکن است برای کیوسک لازم باشد، اما باید با محدودیت نرخ، کنترل ورودی، محدودیت بازه تاریخ و آزمون سوءاستفاده همراه شود. توابع مدیریتی باید فقط برای نقش‌های مجاز قابل اجرا بمانند و کنترل مجوز داخل تابع نیز حفظ شود.

### ۲. گذرواژه‌های افشاشده
قابلیت محافظت Supabase Auth در برابر گذرواژه‌های افشاشده غیرفعال گزارش شده است. فعال‌سازی آن باید در تنظیمات Auth انجام و سپس جریان ثبت‌نام/تغییر رمز آزمایش شود.

### ۳. نقش‌ها و حساب پشتیبان
ساختار فعلی فقط فهرست مدیران مبتنی بر ایمیل را نشان می‌دهد؛ نقش مستقل پشتیبان و کارمند در سطح پایگاه داده هنوز دیده نشد. باید نقش‌ها و مجوزهای دقیق تعریف شوند و حساب پشتیبان مالک در برابر حذف یا غیرفعال‌سازی ناخواسته محافظت شود.

### ۴. حضور مبتنی بر مکان و NFC
در نسخه فعلی ثبت QR/PIN است و منطق NFC یا GPS در کد صفحه کیوسک مشاهده نشد. کنترل فاصله باید سمت سرور انجام شود؛ مختصات ارسالی مرورگر به‌تنهایی قابل اعتماد نیستند. زمان سرور، دقت مکان، جلوگیری از replay، محدودیت نرخ و مسیر رسیدگی دستی باید طراحی شوند.

### ۵. نسخه‌بندی پایگاه داده
در فهرست migrationهای Supabase موردی مشاهده نشد و فایل SQL یا migration در ریشه مخزن نیز وجود نداشت. پیش از تغییر schema باید وضعیت واقعی پایگاه داده مستند و تاریخچه مهاجرت قابل بازتولید ایجاد شود.

## محدودیت‌ها و نکات بررسی
- دو رکورد مدیر وجود داشت؛ آدرس ایمیل آن‌ها عمداً در این گزارش بازنشر نشده است.
- جدول‌های کارکنان و حضور و غیاب در زمان بررسی خالی بودند؛ بنابراین آزمون رفتاری با داده واقعی انجام نشده است.
- کد توابع RPC بررسی شد، اما تست نفوذ، آزمون بار، آزمون عملیاتی مرورگر و بررسی تنظیمات کامل Auth هنوز انجام نشده است.
- مشاور عملکرد یک شاخص استفاده‌نشده را گزارش کرد؛ حذف آن بدون شواهد و سنجش بیشتر توصیه نمی‌شود.
